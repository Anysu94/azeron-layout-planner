# Azeron Layout Planner

A small web tool for planning Azeron gaming-pad layouts: keys colored by category, icons per ability, assignment by drag-and-drop, and generation of import strings for the Azeron software.

No dependencies, no build step: a single `index.html`.

## Features

- Multiple independent profiles (New, Rename, Duplicate, Delete) — each with its own categories, abilities and bindings
- Custom categories with a free color choice (chips at the top right, **Manage** to edit)
- Abilities with name, category and icon (image upload, downscaled to 64×64 PNG)
- **Assigned** and **Unassigned** lists as two full-height side-by-side columns, sorted by category and name
- One shared editor for both pad keys and list entries: name, category (with color dot in the dropdown), key, icon and all key bindings in one place
- **Click any hotkey field** (in the lists or the editor) to open a *Press a key…* popup: just press the key, it is captured and applied immediately. `Space`, `F1`, arrow keys and German characters work without typing names. **Esc** cancels, **Clear** removes the hotkey, and manual typing still works via keyboard focus.
- Drag abilities onto keys; drag keys onto each other to swap
- Drop a key outside the grid (or onto the Unassigned column) to remove its ability
- Export/import all profiles as JSON — includes categories, icons and bindings, so a profile can be moved between browsers/sites with its grouping intact
- Every profile has an **Unassigned** category as a catch-all; abilities imported from the Azeron software or from a keybind string land there (the device export has no category data)
- **Azeron Keybind Export**: generate an `XQAAA…` keybind string that changes only the key assignments of your existing profile
- Saved automatically in the browser

## Where is the data stored?

**Not in the HTML file**, but in the browser under `localStorage` with the key `azl`. This is per browser and per origin:

- **`file://`** (file opened directly): all local files share the same storage. Renaming or moving the file does not lose data.
- **GitHub Pages (`https://…`)**: its own, initially empty storage. Export from the local file once and **Import** on the website.
- **Another browser, another profile, private window** or "clear site data": data is gone.
- **Changing the code** (HTML/CSS/JS) does not delete data. Saved profiles keep their abilities and categories; the **Unassigned** catch-all category is added automatically to older saves on load.
- An older single-layout state (`c`/`a`/`b`) is automatically migrated into a profile named "Standard" on first open. The old data is fully preserved.

The device key-code mapping is fixed in `index.html`. A profile imported from the Azeron software is kept as the export base under `localStorage` key `azbase`. The selected keyboard layout is stored under `azkb`.

A backup of the current state is in `backup/azl-*.json` and can be restored via **Import**. Earlier versions of the planner are in `backup/index-*.html`.

## Local use

Just open `index.html` in a browser.

## Azeron Keybind Export

The planner cannot write to the pad directly. It generates a **keybind** that you paste into the Azeron software. The exported profile carries the **name of your planner profile** (rename it with **Rename**).

1. Click **Generate**.
2. Click **Copy**.
3. In the Azeron software: **Profiles → Keybinds → Paste keybind from clipboard → Apply**.

That is all. There is nothing else to configure.

A built-in device template is used as the base. If you import a profile from the Azeron software, that profile becomes the base instead, so its settings and unmapped inputs are kept. Planner cells map to fixed physical Azeron buttons; keys and ability names from your layout are written onto those buttons. Buttons not used by your layout are copied unchanged from the base profile — including special functions (profile switch, analog stick, mouse codes) which are never normalized.

Note: the keybind only replaces the `inputs` of the target profile and carries your planner profile name. It is **for the device only** and contains no planner categories. To move a profile with its categories from one planner instance to another, use **Export** in **Save / Load** and **Import** on the target site instead.

An ability is transferred as a label even when it has no key. A cell with no ability clears stale labels and keys on that button.

## Import from Azeron exports

Paste an `XQAAA…` string (with or without the fenced wrapper) into the **Save / Load** textarea and click **Import**. Both formats work:

- Software profile exports (`version`/`profiles[]`) — one or more at once.
- Keybind strings generated by this planner (`id`/`name`/`inputs`).

Each becomes a planner profile with abilities built from the input labels and keys; the first imported one also becomes the export base. Since neither format carries planner categories, all imported abilities are placed in the **Unassigned** category. Re-importing a planner-generated string is a round trip: labels, keys and all other input fields stay identical (only the random keybind id changes).

For a full profile transfer **including categories**, use **Export / Import** (Save / Load) instead: click **Export**, copy the JSON, paste it on the other planner instance and click **Import**. Categories, icons and bindings are preserved.

## Keyboard layout

Azeron key codes are physical US/English codes. The planner converts the characters you type into those codes on export, and converts them back on import. **Auto-detect** uses `navigator.keyboard.getLayoutMap()`; if the browser reports the wrong layout, select **German (QWERTZ)** or **English (QWERTY)** manually. The choice is remembered. For example German `Z` → `KeyY`, `Ü` → `BracketLeft`.


## Publish on GitHub Pages

1. Create a new GitHub repository and upload the contents of this folder
2. In the repository: **Settings → Pages**
3. Under **Build and deployment** choose **Deploy from a branch**, branch `main`, folder `/ (root)`
4. Save. After a short while the site is available at `https://<your-name>.github.io/<repo-name>/`

## Notes

- Every visitor has their own state in the browser. Layouts can be shared via Export/Import.
- This tool is not affiliated with Azeron. The actual key assignments are still set in the official Azeron software.
